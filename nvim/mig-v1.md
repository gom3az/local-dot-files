## Phase 11 — Extra native conversions
- [x] **netrw `<C-l>` conflict fix:** netrw installs buffer-local `nmap <buffer> <c-l> <Plug>NetrwRefresh` (netrw.vim:4860/4933) which shadows the global `<C-l>` window-nav → Ctrl+L in the explorer refreshed/re-rendered the tree instead of moving focus right. Fixed in `lua/netrw.lua` via netrw's own override hook: on `FileType netrw`, a buffer-local decoy mapping to `<Plug>NetrwRefresh` makes `hasmapto()` true, so netrw skips binding `<c-l>`; our own buffer-local `<C-l>` → `<C-w><C-l>` takes over. Robust across re-browses (decoy persists → guard stays satisfied). Verified headless: `maparg('<c-l>')` in netrw buf returns `<C-w><C-l>`, `hasmapto('<Plug>NetrwRefresh') == 1`. Kept netrw's `<c-h>` (HideEdit/toggle-hidden) intact.
- [x] **netrw `<leader>e` lag fix (async reveal):** `Lexplore` itself is fast (~135ms); the ~2s lag came from `reveal_current_file` drilling the file's path one directory at a time synchronously — each of N `NetrwBrowseChgDir` re-reads+sorts+re-renders the listing (~97ms each; 7 levels ≈ 680ms), and the mapping blocked until all finished. Replaced the blocking `vim.wait(1500, ...)` with a short (300ms) async first-render wait. ## Phase 14 — formatting.lua: never replace buffer on formatter error (DONE)
- [x] **File-wipe bug (regression from Phase 5):** custom `formatting.lua` used `vim.fn.system(cmd, input)`, which merges stdout+stderr and only checks `v:shell_error`. ktlint exits **0** on a *parse* error (empty stdout, report on stderr), so the guard was bypassed and `nvim_buf_set_lines` replaced the whole file with the merged error report ("Not a valid Kotlin file"). Also, ktlint echoes the *formatted file* to stdout on non-correctable lint errors (exit 1), so error notifications were cluttered with the whole-file echo.
- [x] **Fix:** `format_buffer` now uses `vim.system` with separate streams via a `run_formatter(cmd, input)` helper (`vim.system(cmd, { text = true, stdin = input }, cb)` + `vim.wait(10000, done)`, returns `done, code, stdout, stderr`). Failure = `code ~= 0` **or** (empty stdout **and** buffer had content); on failure it notifies the truncated **stderr-only** report and **returns without touching the buffer**. Success path unchanged (set-lines + eol/view preservation). Note: nvim 0.12.2's `vim.system` takes stdin via **`opts.stdin`**, not `opts.input` (which is silently ignored — verified via `cat`).
- [x] **`<leader>cJ` (jq) hardened too:** was `<cmd>%!jq .<CR>` — `%!` replaces the buffer with jq's output, so invalid JSON wiped the file the same way. Now a Lua mapping through `run_formatter` with the identical fail-safe.
- [x] Verified headless (real config, in-memory): syntax-error `.kt` → buffer preserved + stderr-only notify; lint-error `.kt` (wildcard) → buffer preserved + stderr-only notify; valid `.kt` → still formats; invalid `.json` → buffer preserved + `jq: parse error` notify; valid `.json` → still formats. Clean load (0 errors).
